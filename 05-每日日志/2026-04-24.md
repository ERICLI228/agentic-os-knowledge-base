## 🔧 OpenCode CLI / Desktop 修复记录（04:38 - 05:29 PDT）

### 问题描述
- **错误**: `The 'reasoning_content' in the thinking mode must be passed back to the API`
- **影响**: CLI 和 Desktop 使用 `deepseek-v4-flash` / `deepseek-v4-pro` 开启 thinking 模式时，多轮对话后续请求报 400 错误。
- **根因**: 原始 config 中 `reasoning` 和 `interleaved` 字段放在 `variants` 层级，SDK 只在 `models` 层级读取这些字段。

### 修复动作（CLI ✅ 已修复）
1. **Config 结构重构**: 将 `reasoning: true` 和 `interleaved: {"field": "reasoning_content"}` 从 `variants` 移到 `models` 层级
2. **Config 文件**: `~/.config/opencode/opencode.json`
3. **重启 CLI 服务器**: kill 旧进程，新 PID 82882，端口 55788，`serve` 状态运行中。
4. **验证**: `opencode debug config` 确认配置正确加载；基础模型 `deepseek/deepseek-v4-flash` 可正常工作。
5. **SDK 类型验证**: `/Users/hokeli/.opencode/node_modules/@opencode-ai/sdk/dist/v2/gen/types.gen.d.ts` 确认 `interleaved: true | {field: "reasoning_content"}` 是合法 schema。

### Desktop App 问题（⚠️ 仍未解决）
- **Desktop 版本**: v1.14.22（2026-04-23 发布）
- **架构发现**: Desktop 是 Bun 编译的二进制，二进制路径 `/Applications/OpenCode.app/Contents/MacOS/opencode-cli`，SDK 代码打包在 `chunk-ntzmrqm3.js` 中。
- **数据目录**: `~/Library/Application Support/ai.opencode.desktop/`（含 `opencode.global.dat` 聊天记录、`opencode.settings.dat` 为 `{}`）。
- **Config 路径问题**: 尝试将 `opencode.json` 复制到 `~/Library/Application Support/ai.opencode.desktop/` 后错误仍存在——Desktop 可能不尊重外部 config，或 `interleaved` 在 Bun 运行时中未正确生效。
- **关键限制**: Bun 编译的二进制无法反编译修改，无法 patch SDK 的 interleaved 逻辑。
- **会话历史问题**: 旧会话的聊天历史不含 `reasoning_content` 字段，即使配置修复也必须开启**全新对话**才能生效。
- **CLI variant 解析失败**: `:think-high` / `:think-max` 变体返回 "Model not found"，`opencode models` 输出不包含变体——v1.14.22 可能有变体解析 bug。

### 推荐方案（按优先级）
| 方案 | 操作 | 风险 |
|------|------|------|
| A：换 Reasoner 模型 | 桌面端改用 `deepseek/deepseek-reasoner`（原生 thinking 支持，不需要 interleaved） | 低，需手动切换 |
| B：关闭 reasoning | config 中设 `reasoning: false` | 中，失去深度推理 |
| C：等上游修复 | v1.14.22 是昨天发布版本，interleaved 对 DeepSeek 可能有 bug | 被动等待 |
