## 第一部分：产品概述

### 1.1 产品定位

Agentic OS v3.2 是一个**基于智能体架构的双业务线自动化中台**，通过统一基座管理 TK 跨境电商运营和 AI 数字短剧制作两条独立业务线。产品以"一个指令启动、全程自动执行、关键节点审核"为核心体验，让运营人员和创作者从重复性劳动中解放，专注于高价值的决策和创意工作。

### 1.2 目标用户画像

| 用户角色 | 核心需求 | 使用频率 | 技术水平 |
|----------|----------|----------|----------|
| **TK 运营专员** | 每日查看 GMV/订单/库存简报，处理异常告警，管理达人 | 每日多次 | 中等 |
| **短剧导演/编剧** | 下达短剧创作指令，审核剧本和成片，追踪内容表现 | 每日 1-3 次 | 中等 |
| **技术运维** | 监控系统健康度，处理故障，扩展新业务线 | 按需 | 高 |
| **管理层** | 查看双业务线全局 KPI，审批重大决策 | 每周 | 基础 |

### 1.3 核心价值主张

| 用户 | 当前痛点 | 产品方案 | 价值 |
|------|----------|----------|------|
| TK 运营 | 手动监控、Excel 管订单、达人管理空白 | 自动采集+ERP 闭环 + 达人 CRM | 单人产能从 1 店提升至 5-10 店 |
| 短剧导演 | 月产 1 集、凭感觉写剧本、审核时看不到全貌 | AI 辅助全流程、数据驱动质量迭代 | 周产 3 集，质量可量化 |
| 技术运维 | 新业务线接入需 2-3 周重复开发 | shared/core 基类 + 模板化接入 | 新业务线 3 天内接入 |

### 3.2 TK 运营功能详细说明

#### FR-TK-001:16 品类数据采集

| 属性 | 内容 |
|------|------|
| **优先级** | P0 |
| **触发方式** | Cron 定时 (每 2 小时) |
| **执行角色** | Worker1 选品专家 |
| **输入** | 国家：印尼/越南/泰国/菲律宾/马来西亚，品类：3C 16 个子类 |
| **处理逻辑** | 调用 TikTok API/FastMoss 获取热门视频列表，统计播放量/点赞/评论/分享，提取商品链接和价格信息 |
| **输出** | 品类分布饼图、原始数据 Excel (存储在 `artifacts/`) |
| **异常处理** | API 返回空时重试 3 次，仍失败则标记 MS-1 为 failed 并飞书告警 |
| **验收标准** | 单次采集<5 分钟，采集成功率>95% |

#### FR-TK-006:ROI 异常检测 + 早期爆款预测

| 属性 | 内容 |
|------|------|
| **优先级** | P1 |
| **触发方式** | FR-TK-005 完成后自动触发 |
| **执行角色** | Worker3 广告专家 |
| **输入** | 广告账户 ROAS 数据、视频前 4 小时互动数据 |
| **处理逻辑** | 1) 检查 ROAS<150% 的广告组，标记异常；2) 用前 4 小时点赞率/完播率/评论情感训练轻量级预测模型，判断是否可能成为爆款（替代滞后 300 万规则） |
| **输出** | ROI 趋势折线图、异常广告列表、爆款预测标记 |
| **决策点** | ⚠️ ROI<100% 时创建决策点：暂停广告/调整预算/忽略 |
| **验收标准** | 告警延迟<30 分钟，预测准确率>70% |

#### FR-TK-007：订单拉取与校验

| 属性 | 内容 |
|------|------|
| **优先级** | P0 (需店小秘 API Key) |
| **触发方式** | Cron 定时 (每 30 分钟) 或手动触发 |
| **执行角色** | Worker1 选品专家 |
| **输入** | 店小秘 API 凭证 |
| **处理逻辑** | 调用店小秘 API 获取新订单列表，校验订单状态/金额/地址完整性，写入本地数据库 |
| **输出** | 订单量趋势图、异常订单列表 |
| **依赖** | 店小秘 API Key (待获取) |
| **验收标准** | 订单同步延迟<5 分钟，数据完整率>98% |

#### FR-TK-012：运营简报生成

| 属性 | 内容 |
|------|------|

### 3.3 AI短剧功能详细说明

#### FR-DR-001：剧本生成（含编剧规则引擎）

| 属性 | 内容 |
|------|------|
| **优先级** | P0 |
| **触发方式** | 用户在驾驶舱输入主题/风格/集数/时长后触发 |
| **执行角色** | Worker4 短剧剧本 |
| **输入** | 故事主题、视觉风格、集数、目标时长、编剧规则参数 |
| **处理逻辑** | 1) 编剧规则引擎校验输入（钩子位置/反转频率/结尾悬念）；2) 调用 Dify API (MiniMax/GLM) 生成结构化剧本 JSON；3) 校验输出格式完整性 |
| **输出** | 结构化剧本 JSON (含场景/角色/对话/情绪/时长) |
| **成本路由** | 优先 Dify+MiniMax ($0-0.5)，降级 GLM API |
| **验收标准** | 剧本包含≥5 个场景，每场景≥2 句对话，符合编剧规则 |

#### FR-DR-005:AI 质量自评

| 属性 | 内容 |
|------|------|
| **优先级** | P1 |
| **触发方式** | FR-DR-004 完成后自动触发 |
| **执行角色** | QA 陈小兰 |
| **输入** | 完整剧本 JSON + 分镜视频片段 |
| **处理逻辑** | 调用 GLM/Claude 进行结构化评分：故事张力 (1-10)、角色一致性 (1-10)、冲突强度 (1-10)、对话自然度 (1-10)；综合分=加权平均；低于阈值 (默认 6.5) 自动回流 MS-1 重新生成 (最多 3 次) |
| **输出** | 结构化评分 JSON，含改进建议 |
| **验收标准** | 评分延迟<3 分钟，阈值可配置，回流逻辑正确 |

#### FR-DR-006：增强人工审核

| 属性 | 内容 |
|------|------|
| **优先级** | P0 |
| **触发方式** | AI 自评通过 (或跳过自评) 后触发 |
| **执行角色** | 用户 (Human) |
| **输入** | 无（系统自动聚合并展示） |
| **审核面板内容** | ① 完整剧本（标注情绪/节奏/关键 pose）；② 分镜缩略图（按时间轴排列）；③ 配音小样试听（自动播放）；④ 时长估算（每场戏/总计）；⑤ AI 评分报告（含改进建议） |
| **决策选项** | [通过] → 继续 MS-6；[修改] → 输入修改意见 → 回到 MS-1 保留上下文；[驳回] → 任务终止 |
| **通知方式** | 驾驶舱弹窗 + 飞书审核卡片（含缩略图和关键信息） |
| **验收标准** | 所有信息一目了然，用户无需跳转到其他页面 |

#### FR-DR-010：完播率追踪

| 属性 | 内容 |
|------|------|
| **优先级** | P2 |
| **触发方式** | 短剧发布后自动启动 |
| **执行角色** | Worker4 短剧剧本 |
| **输入** | TikTok 视频 ID |
| **处理逻辑** | 每小时调用 TikTok API 获取视频分析数据：完播率、平均观看时长、观众划走时间分布、评论情感分析；数据回流至编剧规则引擎，优化评分阈值和钩子位置规则 |
| **输出** | 完播率趋势图、划走时间分布热力图、评论情感饼图 |
| **验收标准** | 数据每小时更新，回流逻辑自动生效 |

### 3.4 基座功能详细说明

#### FR-BS-001：任务追踪器

| 属性 | 内容 |
|------|------|
| **实现方式** | JSON 文件 + fcntl 文件锁 |
| **核心能力** | 创建任务、更新状态、添加里程碑、添加决策点、查询任务列表 |
| **并发安全** | fcntl.LOCK_EX 排他锁，10 进程并发测试通过 |
| **数据隔离** | 按 project_id 分目录存储 |

#### FR-BS-002:Token 预算控制器

| 属性 | 内容 |
|------|------|
| **预算分配** | TK 运营 60%、AI短剧 40% |
| **核心逻辑** | 按 project_id 分账，每次 API 调用前检查余额；余额不足时拦截并告警；支持按 KPI 动态调整权重（带反死亡螺旋门禁） |
| **存储方式** | JSON 文件 + 原子写入 (os.replace) |

#### FR-BS-003：技能路由校验

| 属性 | 内容 |
|------|------|
| **核心逻辑** | 加载 registry.yaml，校验任务 ID 前缀与 skill 的 compatible_tasks 是否匹配 |
| **失败动作** | 立即终止任务调度，飞书 P0 告警，记录到 execution_logs |
| **验收标准** | 100% 拦截跨业务线路由 |

## 第五部分：用户流程

### 5.1 TK 运营核心流程

```
[每日 08:00] 运营人员打开飞书
 │
 ├── 收到运营简报卡片
 │ └── 显示：昨日 GMV | 订单量 | TOP SKU | 库存告警 | 达人动态
 │
 ├── 有异常？(ROI 下降/库存不足/订单异常)
 │ ├── 点击详情 → 跳转驾驶舱查看完整数据
 │ └── 处理决策：调整广告/确认补货/处理异常订单
 │
 └── 无异常？→ 完成，继续其他工作

[实时] 驾驶舱监控
 │
 ├── 突发异常时飞书告警
 │ └── 运营人员打开告警卡片 → 查看详情 → 决策
 │
 └── 每日下午复盘：打开驾驶舱 → TK 项目视图 → 查看各里程碑产出
```

### 5.2 AI短剧核心流程

```
[创作者] 打开驾驶舱 → 点击 "+新建短剧"
 │
 ├── 填写：故事主题、视觉风格、集数、目标时长
 │
 ▼
[系统] 自动执行 MS-1~MS-4
 │
 ├── 编剧规则引擎校验
 ├── Dify 生成剧本
 ├── GLM 争议改写
 ├── 视觉圣经 + 角色设计

 └── AI 质量自评 → <阈值自动回流
 │
 ▼
[创作者] 收到审核通知 (驾驶舱弹窗 + 飞书卡片)
 │
 ├── 打开审核面板
 │ ├── 查看完整剧本
 │ ├── 查看分镜缩略图
 │ ├── 试听配音小样
 │ └── 查看 AI 评分报告
 │
 ├── 选择：[通过] → 自动继续 MS-6~MS-8
 │ [修改] → 输入意见 → 回到 MS-1
 │ [驳回] → 任务终止
 │
 ▼
[系统] 自动执行 MS-6~MS-8 → 产出 MP4
 │
 ▼
[创作者] 收到完成通知 → 下载/发布视频
 │
 ▼
[系统] 发布后追踪完播率 → 数据回流优化编剧规则
```

### 5.3 异常处理流程

```
[异常发生] 任一步骤执行失败
 │
 ├── 自动重试 (最多 3 次，间隔 5 分钟)
 │
 ├── 3 次后仍失败？
 │ ├── 创建决策点
 │ ├── 里程碑标记为 failed
 │ ├── 飞书告警
 │ └── 暂停该任务后续步骤
 │
 └── 用户收到告警 → 查看日志 → 决策：重试/跳过/中止
```

## 第七部分：技术约束与决策

### 7.1 技术选型约束

| 约束项 | 决策 | 理由 |
|--------|------|------|
| 数据库 | SQLite + JSON 文件 | 数据量小，无需外部依赖，文件锁保证并发安全 |
| 后端框架 | Python Flask | 已有代码基础，团队熟悉 |
| 前端框架 | Vue 3 + Vite | 已部署，组件化开发 |
| 进程守护 | pm2 | macOS 兼容，简单可靠 |
| 模型路由 | 本地优先→云端降级 | 成本最低原则 |
| 跨 APP 调度 | MCP 协议 | 标准化接口，解耦执行端 |

### 7.2 明确不做的事

| 不做的事 | 理由 |
|---------|------|
| ORM 迁移 | 数据量不到，过度工程 |
| 完整单元测试套件 | 当前阶段代码快速变化，等稳定后补 |
| 第三条业务线 | 先验证两条线的经济模型 |
| 微服务拆分 | 当前单体架构已够用 |
| Kubernetes 部署 | 单机部署场景，过度复杂 |
