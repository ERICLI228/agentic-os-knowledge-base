# Agentic OS v3.2 终极架构文档

> **设计原则**: 一个基座、两条业务线、独立运营、共享预算  
> **核心体验**: 一个指令启动 → 全程自动执行 → 关键节点审核 → 输出可发布成果  
> **思想内核**: 自进化智能体框架 + GSTACK 专家团队分工 + 行业最佳实践融合  
> **审视加持**: TK 运营老兵 + 短剧制作人 双视角深度校验  
> **版本**: v3.2 | **日期**: 2026-04-23

---

## 序言：v3.2 相比 v3.1 的升级点

本版本基于两位 20 年经验老兵的联合审视，对 v3.1 进行全面重构：

| 升级维度 | v3.1 | v3.2 |
|---------|------|------|
| **TK 业务视角** | 技术驱动的 14 个里程碑 | 运营视角的 4 大阶段，增加 `daily_business_summary.py` |
| **短剧内容视角** | 线性流水线 | 增加 AI 质量自评节点、视觉圣经机制、完播率追踪 |
| **审核界面** | 简单通过/修改/驳回 | 增强审核：剧本全文 + 分镜缩略图 + 配音试听 + 时长估算 |
| **架构设计** | 静态架构图 | 深度融合 GSTACK 专家团队分工 + 双智能体模式 |
| **成本控制** | Token 预算分配 | 增加智能路由（本地免费优先→云端降级） |
| **执行路线** | 按优先级排序 | 修正为不对称管理：TK 先止血，短剧先验证质量 |

## 第一部分：自进化智能体思想框架

### 1.1 双智能体架构

**理论来源**: Anthropic 长时间运行智能体研究

```
┌─────────────────────────────────────────────┐
│ 初始化智能体 (Initializer)                  │
│ • 建立结构化环境                            │
│ • 创建 task.json, progress.txt, cloud.md    │
│ • 定义任务拆解策略                          │
└─────────────────────┬───────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────┐
│ 编码智能体 (Coder Agent)                    │
│ • 逐会话增量推进                            │
│ • 保持代码干净状态                          │
│ • 记忆传承 (通过结构化工件而非上下文压缩)    │
└─────────────────────────────────────────────┘
```

**在 Agentic OS 中的映射**:
- **运营总监（初始化智能体）**: 接收用户指令 → 拆解任务 → 分配执行 → 收集反馈 → 优化策略
- **各专业 Agent（编码智能体）**: 执行具体任务（选品/内容/广告/剧本/视频/配音），通过结构化工件传承上下文

### 1.2 编排者 - 工作者模式

**理论来源**: Anthropic 多智能体生产系统

```
                    ┌──────────────┐
                    │  编排者 (CEO) │
                    │   黄光耀      │
                    └──────┬───────┘
                           │
    ┌──────────┬───────────┼───────────┬──────────┐
    │          │           │           │          │
    ▼          ▼           ▼           ▼          ▼
┌─────────┐┌─────────┐┌─────────┐┌─────────┐┌─────────┐
│Worker1  ││Worker2  ││Worker3  ││Worker4  ││Worker5  │
│选品专家 ││内容专家 ││广告专家 ││短剧剧本 ││短剧视频 │
└─────────┘└─────────┘└─────────┘└─────────┘└─────────┘
```

**关键发现**:
- Token 用量解释 80% 的性能方差，多智能体系统消耗约 15 倍于普通聊天的 token
- 需为高价值任务保留资源，低价值任务使用降级模型
