# Agent Skill — Code Simplification (`/code-simplify`)

## 触发词

`/code-simplify`、"简化代码"、"重构这段代码"、"清理代码"、"这代码太复杂了"

## 核心原则

**目标不是更少的行数——而是更容易阅读、理解、修改和调试的代码。**

## 简化机会识别

| 模式 | 信号 | 简化方法 |
|------|------|---------|
| 深层嵌套（3+层） | 控制流难跟踪 | 提取为守卫子句或助手函数 |
| 长函数（50+行） | 多重职责 | 拆分为专注函数 |
| 嵌套三元 | 需要脑容量解析 | 替换为 if/else 或 switch |
| 布尔参数标记 | `doThing(true, false)` | 替换为选项对象 |
| 重复条件 | 同一 if 检查多处出现 | 提取为命名谓词函数 |
| 通用命名 | `data`, `result`, `temp` | 重命名描述内容 |
| 重复逻辑 | 相同 5+ 行多处 | 提取为共享函数 |
| 死代码 | 不可达分支、未使用变量 | 移除 |

## 核心原则

1. **精确保持行为** — 输入、输出、副作用、错误行为必须完全相同
2. **遵循项目约定** — 简化是让代码更符合代码库
3. **清晰优于聪明** — 1 行嵌套三元不比 5 行 if/else 更简单
4. **保持平衡** — 避免过度内联或合无关逻辑
5. **范围限于变更内容** — 默认只简化最近修改的代码

## Chesterton's Fence

> 看到路中间有栅栏，不要急着拆除。先理解为什么在那里。

简化前回答：这段代码的职责是什么？边界情况是什么？有测试吗？
